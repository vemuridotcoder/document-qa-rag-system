# Results and Methodology

## Summary
This project tracks retrieval quality and system latency as first-class production metrics.

## Artifacts
- `evaluation/results_before.json`
- `evaluation/results_after.json`
- `evaluation/retrieval_results.json` (generated by `src/evaluate.py`)
- `evaluation/latency_benchmark.json` (generated by `src/benchmark.py`)

## Method
1. Ingest evaluation corpus.
2. Run retrieval evaluation (`python src/evaluate.py`) for Hit@K + MRR.
3. Run latency benchmark (`python src/benchmark.py`) for P50/P95/P99.
4. Compare against prior snapshot and quality gates.

## Interpreting metrics
- **Hit@K**: higher is better retrieval recall in top-K.
- **MRR**: higher means relevant chunks appear earlier.
- **P95/P99 latency**: lower means better tail-latency and UX under load.
- **Cache hit rate**: higher means better cost + latency efficiency for repeated queries.
